# 1+1 ➳ поиск объектов

Сайт, где можно искать квартиры, новостройки, дома, участки и коммерцию Краснодара,
которые риелторы присылают в чаты WhatsApp / Telegram / MAX.

Как это работает:

1. **worker** каждые 1–2 минуты забирает новые сообщения из Wappi (только читает по API —
   настройки Wappi и рассылка не затрагиваются).
2. Каждое сообщение разбирается: нейросеть DeepSeek (один запрос на сообщение) +
   проверка правилами. Если ключа DeepSeek нет — разбор только правилами.
3. Одинаковые объекты от разных агентов и из разных чатов склеиваются в один.
4. **web** — сам сайт: поиск, фильтры, карта, карточка объекта.
   Покупатели видят общий контакт, коллеги после ввода кода — телефоны агентов.
5. **caddy** — «входная дверь»: принимает посетителей и сам получает HTTPS-сертификат.
6. **bot** — Telegram-бот: вход на сайт с подтверждением номера, «убрать мой номер»
   для агентов, уведомления владельцу о сбоях.

Личный кабинет: вход через Telegram или по почте, избранное. Номера агентов видны
только с доступом: неделя бесплатно после подтверждения номера (раз на номер), дальше
подписка. Админка — `https://<адрес сайта>/admin` (вход через Telegram владельца).

Работает на **отдельном сервере** (Timeweb Cloud, Ubuntu 24.04) — старое приложение
с рассылкой никак не затрагивается. Всё хранится в одном файле `data/strely.db`.

## Установка (один раз)

Все команды вставляются в окно SSH на новом сервере.
Вставить в окно терминала — правая кнопка мыши.

### 1. Подключиться к серверу

На своём компьютере откройте PowerShell и выполните:

```bash
ssh root@31.130.132.118
```

Пароль — из карточки сервера в Timeweb (при вводе он не отображается — это нормально).
Можно и без PowerShell: в карточке сервера в Timeweb есть кнопка «Консоль».

### 2. Скачать проект и подготовить сервер

```bash
git clone https://github.com/kifakifakefidron-tech/1-1.git /opt/1plus1
```
```bash
cd /opt/1plus1 && bash setup.sh
```

`setup.sh` ставит Docker, создаёт папку для базы и файл настроек `.env`,
включает защиту (открыты только SSH и сайт). В конце пишет адрес сайта.

### 3. Вписать настройки

```bash
nano .env
```

- `ACCESS_CODE` — код для коллег (можно по-русски);
- `FEED_PHONE` — телефон партнёра для объектов фида (виден только подписчикам);
- `DEEPSEEK_API_KEY` — ключ с platform.deepseek.com (можно позже);
- `WAPPI_TOKEN` и `WAPPI_PROFILES` — **можно оставить пустыми** на первый запуск:
  сайт заработает, просто без новых объявлений. Подключим отдельным шагом.

Сохранить: `Ctrl+O`, `Enter`. Выйти: `Ctrl+X`.

### 4. Запустить

```bash
docker compose up -d --build
```

Первый раз собирается 2–4 минуты. Проверка:

```bash
docker compose ps
```

Все три сервиса (`caddy`, `web`, `worker`) — в состоянии `running` / `Up`.
Откройте в браузере адрес из `SITE_DOMAIN` (например `https://31-130-132-118.sslip.io`).
Сертификат получается в первую минуту — если браузер сразу ругается, подождите и обновите.

## Вход по почте (Яндекс)

1. Заведите отдельный ящик на Яндексе, например `odinplusodin.poisk@yandex.ru`.
2. Яндекс ID → «Безопасность» → «Пароли приложений» → «Почта» → создать. Скопируйте пароль.
3. На сервере впишите в `.env` `SMTP_USER=<ящик>` и `SMTP_PASSWORD=<пароль приложения>`
   и выполните `docker compose up -d`.

## Свой домен

1. Купите домен у регистратора (например, в Timeweb — там же, где сервер; .ru стоит ~200–900 ₽ в год).
2. В настройках DNS домена добавьте две записи **A** → `31.130.132.118`:
   имя `@` (сам домен) и имя `www`. Подождите 15–60 минут, пока записи разойдутся.
3. На сервере: `cd /opt/1plus1 && nano .env` и поменяйте/добавьте строки:
   ```
   SITE_DOMAIN=ваш-домен.ru
   OLD_DOMAINS=31-130-132-118.sslip.io, www.ваш-домен.ru
   ```
4. `docker compose up -d` — Caddy сам получит сертификаты; старый адрес и www будут
   перенаправлять на новый (старые ссылки, подборки и календари продолжат работать).
5. Проверка: откройте `https://ваш-домен.ru` и старый адрес — он должен перебросить на новый.


## Оплата через ЮKassa (самозанятый)

**Что уже готово на сайте:** страница оплаты `/pay` (тарифы, карта, «Готово»), проверка платежа через API ЮKassa,
продление доступа после оплаты, страницы «Пользовательское соглашение» и «Политика». Данные карт сайт не видит —
человек платит на странице ЮKassa.

1. **Проверить статус самозанятого** в приложении «Мой налог» (ИНН, статус НПД). Ограничения: оплата только от
   физлиц, доход до 2,4 млн ₽ в год; работать с юрлицами нельзя.
2. **Заполнить реквизиты на сайте** (их проверит ЮKassa): на сервере `nano .env` →
   `OPERATOR_NAME=Фамилия Имя Отчество`, `OPERATOR_INN=…`, `CONTACT_EMAIL=…`, затем `docker compose up -d`.
   Проверить, что на `/terms` и `/privacy` подставились ФИО, ИНН и почта. Текст оферты лучше показать юристу.
3. **Заявка в ЮKassa:** yookassa.ru → «Подключиться» → «Я самозанятый» → ИНН, паспорт, телефон →
   адрес сайта `https://1plus1assistant.ru` → что продаёте: «Доступ к онлайн-сервису поиска объектов недвижимости
   (подписка)». ЮKassa проверит сайт: должны открываться цены (`/pay`), оферта, контакты.
4. **После одобрения**, в личном кабинете ЮKassa:
   * «Интеграция» → «Ключи API» → выпустить **секретный ключ** (показывается один раз) и посмотреть **shopId**;
   * «Интеграция» → «HTTP-уведомления» → адрес `https://1plus1assistant.ru/api/payments/yookassa`,
     событие `payment.succeeded` (и `payment.canceled`);
   * «Настройки» → «Чеки» → подключить **«Мой налог»** — чеки будут уходить в налоговую и покупателю сами.
5. **Включить оплату на сервере:** `nano .env` → добавить
   ```
   PAYMENTS_ENABLED=true
   YOOKASSA_SHOP_ID=…
   YOOKASSA_SECRET=…
   ```
   Цены уже заданы в программе: первая неделя 49 ₽ (один раз), дальше 99 ₽ за 7 дней или 399 ₽ за 30 дней.
   Поменять — строками `SUB_PLANS=7:99,30:399` и `SUB_FIRST=7:49` («дней:цена»). Старые строки `SUB_PRICE=…` и
   `SUB_PLANS=7:49,30:179,90:449` можно удалить — они больше не действуют. → `docker compose up -d`.
6. **Проверить:** открыть `/pay`, оплатить самый дешёвый тариф своей картой → вернуться на сайт →
   «Доступ открыт»; в кабинете — новая дата доступа; в «Мой налог» — чек. Если что-то не так —
   `docker compose logs --tail 50 web`.

## Отдельный адрес для подборок клиентам

Чтобы клиент, получивший подборку, не видел адрес сервиса и не мог зайти на него в обход агента:
1. Купите на reg.ru нейтральный домен (например, `podborka-kvartir.ru`) — без «1+1» и без вашего бренда.
2. В DNS домена добавьте A-запись `@` → `31.130.132.118`.
3. На сервере: `echo PICK_DOMAIN=podborka-kvartir.ru >> /opt/1plus1/.env && cd /opt/1plus1 && docker compose up -d`.

После этого ссылки на подборки сами станут вида `https://podborka-kvartir.ru/c/…`, старые ссылки переадресуются,
а на этом адресе открывается только подборка — остальные страницы отвечают «не найдено».

## Безопасность и резервные копии

**Копия базы** делается сама каждую ночь (после 3:00 по Москве) в `data/backups/` — хранятся последние 7 дней
(сжатые, `1plus1-ГГГГ-ММ-ДД.db.gz`). Не удалась — придёт уведомление. Копия лежит на том же сервере: от поломки файла
и ошибочной правки спасёт, от потери сервера — нет. Раз в неделю скачивайте свежую копию к себе (с компьютера):

    scp root@31.130.132.118:/opt/1plus1/data/backups/$(ssh root@31.130.132.118 'ls -t /opt/1plus1/data/backups | head -1') .

Восстановить из копии (на сервере):

    cd /opt/1plus1 && docker compose stop web worker bot
    gunzip -c data/backups/1plus1-ГГГГ-ММ-ДД.db.gz > data/strely.db && rm -f data/strely.db-wal data/strely.db-shm
    docker compose up -d

Фото агентов (`data/photos`) в копию базы не входят — их можно скачать так же (`scp -r`).

**Файл с паролями** `.env` должен читать только владелец:

    chmod 600 /opt/1plus1/.env

**SECRET_KEY** в `.env` — длинная случайная строка (её ставит `setup.sh`). Если её нет — придёт предупреждение;
задать: `echo SECRET_KEY=$(openssl rand -hex 32) >> .env && docker compose up -d`.

Что уже сделано на стороне сайта: пароли не хранятся (вход по коду), коды и сессии — только в виде хеша, админские
разделы проверяют админа на сервере, ссылки из писем подписаны, номера агентов — по одному и с дневным лимитом,
запросы больше 15 МБ отбрасываются, браузеру включена защита (HTTPS-only, запрет встраивания чужими сайтами),
Caddy не получает пароли из `.env`, журналы контейнеров ограничены по размеру.

## Нагрузка

`WEB_WORKERS` в `.env` = число ядер сервера (`nproc`). Файлы сайта и фото отдаёт Caddy, ответы поиска/фильтров/карты
сайт запоминает на 15–60 с и считает один раз для всех одновременных одинаковых запросов.
Проверка: `python scripts/loadtest.py https://1plus1assistant.ru 300 60` (лучше запускать с другого сервера —
домашний интернет сам становится узким местом).

## Каждый день

Сначала зайти в папку проекта: `cd /opt/1plus1`

| Что нужно | Команда |
|-----------|---------|
| Что делает worker | `docker compose logs -f --tail 50 worker` (выход — `Ctrl+C`) |
| Обновить после изменений на GitHub | `git pull && docker compose up -d --build` |
| Применить изменения в `.env` | `docker compose up -d` |
| Перезапустить | `docker compose restart` |
| Остановить | `docker compose down` |
| Копия базы | `cp data/strely.db data/strely-$(date +%F).db` |
| Статистика | `curl -s http://127.0.0.1:8090/api/stats` |

В логах worker каждые полторы минуты строка вида
`цикл: {'new_messages': 12, 'processed': 12, 'geocoded': 3, 'archived': 0}`.

Объект пропадает из поиска, если его не присылали 45 дней (`STALE_DAYS` в `.env`).
