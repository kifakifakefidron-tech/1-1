# СТРЕЛЫ · поиск объектов (strely-search)

Новое отдельное приложение для поиска объектов недвижимости Краснодара из
риелторских чатов. Пишется С НУЛЯ на основе опыта старого проекта FindHouse
(репозитории kifakifakefidron-tech: FindHouseBackend, find_house_frontend,
whatshapp_ai_agents-new, WaFindHouse-new). Старое приложение и рассылку НЕ ТРОГАЕМ.

Пользователь (Артём) — не программист, работает с риелторами Краснодара
(сайт arrowsrealty.ru, бренд «СТРЕЛЫ»). Объясняй простыми словами, по-русски.

## Принятые решения
- Сообщения берём из Wappi **по API (опрос раз в 1–2 мин)**, webhook НЕ переключаем —
  иначе старое приложение перестанет получать сообщения.
- Запуск — на **ОТДЕЛЬНОМ сервере** Timeweb Cloud `31.130.132.118` (Ubuntu 24.04,
  папка `/opt/1plus1`), чтобы не задеть старое приложение с рассылкой (она критична, 24/7).
  На старый сервер не заходим.
- Сервис называется **«1+1»**, отдельно от бренда СТРЕЛЫ и домена arrowsrealty.ru
  (домен там на Тильде). Домен — `1plus1assistant.ru` (с 12.10; до этого `31-130-132-118.sslip.io`, перенаправляется).
  HTTPS — Caddy в docker-compose (`Caddyfile`, адрес из `SITE_DOMAIN` в `.env`).
- Подготовка сервера — `setup.sh` (Docker, data/, .env с SECRET_KEY и SITE_DOMAIN, ufw).
- Пароли/ключи пользователь вписывает в `.env` на сервере сам; в чат их не присылать.
- Нейросеть — **DeepSeek** (уже оплачен), ОДИН запрос на сообщение вместо 5–7.
- В базу идут все типы: вторичка, новостройки, дома/участки, коммерция; продажа и аренда.
- Аудитория: коллеги-риелторы (видят телефоны агентов по коду доступа) и
  покупатели (видят только контакт СТРЕЛ). Telegram не обязателен — обычный сайт.
- Стек выбран минимальный: Python 3.11+, Starlette + uvicorn, SQLite (+FTS5),
  стандартный urllib для HTTP. Без Postgres/Redis/RabbitMQ.

## Проблемы старой системы, которые решаем (подтверждены скриншотами)
1. **Дубли.** Старый бэкенд сравнивал «похожие» объекты только внутри одного
   подключённого номера (bot_id), объявления без адреса не проверял вообще,
   отпечаток = телефон+адрес (другой агент → новый объект).
   → `app/dedupe.py`: сравнение по всей базе по характеристикам; репосты одного
   текста распознаются по хешу и НЕ гоняются через нейросеть повторно.
2. **Заголовок ≠ описание.** «Площадь: 20 сот» → «Участок, 20 м²»; участку в хуторе
   приписан «ЖК МОЗАИКА» и район «Теплоэлектроцентраль» (LLM угадывал «по знанию
   Краснодара»). → `rules.py` различает сотки/м²; `geo.py` ставит ЖК/район только
   если они есть в тексте или однозначно следуют из ЖК/улицы по справочнику.
3. **Описание резалось** по пустым строкам до одного абзаца.
   → `rules.split_objects` режет только если в сообщении несколько цен.
4. **Поиск «движение» → 1058 объектов** (нечёткое сходство по длинным текстам).
   → FTS5 по словам с простым стеммингом (`search.py`).
5. **Карта**: подложка Carto без ключа («API KEY REQUIRED»), карта игнорировала фильтры.
   → OSM-тайлы, точки карты по тем же фильтрам; координаты — Nominatim с кэшем.

## Структура
- `app/config.py` — настройки из `.env`
- `app/textnorm.py` — нормализация текста (ё→е, регистр)
- `app/geo.py` + `app/data/geo_kb_raw.json` — районы (канон + жаргон: ФМР, Восточка, РИП…),
  377 ЖК, 1155 улиц (из geo_kb.sqlite старого проекта)
- `app/rules.py` — разбор правилами: цена, площадь/сотки, комнаты, этаж, телефоны, улица, тип, сделка, «куплю/ищу»
- `app/llm.py` — один запрос к DeepSeek, строгая JSON-схема
- `app/parser.py` — объединение ответа нейросети и правил, выбрасывает всё, чего нет в тексте
- `app/dedupe.py` — склейка дублей
- `app/ingest.py` — сохранить сообщение → разобрать → создать/обновить объект; заголовок, индекс
- `app/search.py` — фильтры, сортировки, фасеты, точки карты, карточка с историей.
  Строка поиска разбирается `interpret()`: «2к/однушка/студия/евро2» → фильтр комнат,
  район в любом написании → OR по всем его названиям, остальное — FTS по началу слова.
  Районы — только канонические из `geo.DISTRICTS` (иначе дубли в фильтре).
- `app/wappi.py` — опрос Wappi. WhatsApp: `/api/sync/messages/all/get`. У Telegram и MAX
  такого метода НЕТ (по докам wappi.pro): `{tapi|maxapi}/sync/chats/get` → группы с
  last_timestamp новее курсора → `.../messages/get?chat_id=…&mark_all=false`. MAX отдаёт
  время в миллисекундах. `/tapi/sync/chats/get` в доках не найден явно — проверить по журналу.
  Настройки: WAPPI_TOKEN_{WA,TG,MAX} + WAPPI_PROFILE_{WA,TG,MAX} (только ID), WAPPI_ENABLED.
  Проверено на реальном токене 06.10.2026: WA и TG работают (`/tapi/sync/chats/get` есть).
  Wappi НЕ соблюдает параметр date — отдал ~18 000 сообщений истории. Поэтому
  order=desc и остановка на курсоре (`_fresh`). Очередь разбирается от новых к старым,
  не дольше 60 с за цикл; старше STALE_DAYS — status='skipped'.
  В сообщениях WA нет названия группы (chat name пуст) — можно брать из /api/sync/chats/get.
- `app/agent.py` + `web/agent.js` — кабинет агента: номер подтверждается кодом «1+1-XXXXXX», который агент
  шлёт СО СВОЕГО номера на VERIFY_NUMBER в MAX/WhatsApp (wappi.py смотрит личку только пока есть ожидающие коды;
  номер отправителя: WA — chatId «7918…@c.us», у MAX поле пока не проверено — смотреть журнал «личное сообщение»).
  Править можно объявления со своим номером; первый правящий = owner_user_id, остальным закрыто.
  Чат-объявления: цена/описание/фото/продано; свои (source='own', только с подпиской): все поля, живут
  OWN_LISTING_DAYS, за 3 дня письмо со ссылками /agent/confirm (HMAC), «нет» — снят сразу, игнор — по сроку.
  Журнал listing_edits, откат в админке. Фото: браузер сжимает до 1600 px → data/photos/<id>/<hash>.jpg.
  Повтор поста из чата не перетирает цену/описание владельца и не возвращает «продано» (3 дня).
- `app/hooks.py` — фишки: подписки на поиск (saved_searches, письмо раз в ≤3 ч, отписка /saved/off),
  снижение цены в избранном (favorites.price_at/notified_price; триггер trg_price_change пишет prev_price),
  «продают ещё N агентов» (same_elsewhere), медиана ₽/м² по ЖК/району (market_for, «ниже рынка» ≤ −7 %), заметки.
- `app/region.py` — пока только Краснодар: BLOCKED_PLACES (Сочи, Адлер, Сириус, Туапсе…) по названию чата
  и населённому пункту; названия групп WA — `wappi.refresh_chat_names` раз в 6 ч (таблица chats).
- `app/audit.py` — отчёт о потерях (комнаты, ЖК, районы, карта, чужие города), `--fix` исправляет.
  `scripts/loadtest.py` — нагрузка. Локально (ПК Артёма, 2 воркера): 100 пользователей — ответ 0,02 с.
- Фильтр ЖК — по `cxkey()` (SQLite-функция = geo.complex_key): разные написания одного ЖК совпадают.
- Карта: geocode.candidates — дом → ЖК → улица → посёлок → район (geo_status 'approx', пунктирный ценник).
- Объекты СТРЕЛ (фид) сортируются вместе со всеми, без вывода вперёд и без метки (решение 07.10).
- Кэш /api/listings, /api/facets, /api/map — 15 с в памяти; state cache_ver сбрасывает при правках агентов/админа.
- 07.10 ночь (решения Артёма): аренда только при явных словах (`rules.detect_deal`, нейросети не верим);
  объекты без района/ЖК/улицы/посёлка не показываются (`search._where`); адрес отдельной строкой —

## Разбор «портянок» (07.10.2026, по реальным данным)
- Цена в тысячах: «Цена 3200» = 3,2 млн; «7,8🍋» = млн; «5600 💰», «🪙5500»; цифры-эмодзи 4⃣9⃣0⃣0⃣.
- Не цена: обременение, «в дкп», задаток, комиссия (`_NOT_PRICE_BEFORE`), если рядом нет «цена».
- Портянка без пустых строк режется по строкам с ценой (`_split_by_lines`), хвосты вроде
  «Заклад обсуждаем» остаются у объекта; общий хвост делится между всеми, только если с телефоном.
- Этаж: «Этаж 17» важнее дроби; «ул. Домбайская 17/25», «39/2к7» — номер дома.
- Нейросеть получает пронумерованные строки и отвечает диапазонами `lines` (не переписывает
  текст — раньше ответ обрезался на длинных подборках). Подписанная цена из правил важнее
  цены нейросети. Если правила нашли больше объектов — берём разбивку правил.
- Описание объекта = его кусок текста целиком без телефонов.
