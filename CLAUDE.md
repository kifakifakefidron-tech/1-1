# СТРЕЛЫ · поиск объектов (strely-search)

Новое отдельное приложение для поиска объектов недвижимости Краснодара из
риелторских чатов. Пишется С НУЛЯ на основе опыта старого проекта FindHouse
(репозитории kifakifakefidron-tech: FindHouseBackend, find_house_frontend,
whatshapp_ai_agents-new, WaFindHouse-new). Старое приложение и рассылку НЕ ТРОГАЕМ.

Пользователь (Артём) — не программист, работает с риелторами Краснодара
(сайт arrowsrealty.ru, бренд «СТРЕЛЫ»). Объясняй простыми словами, по-русски.

## Принятые решения
- Сообщения берём из Wappi **по API (опрос раз в 1–2 мин)**, webhook НЕ переключаем —
  иначе старое приложение перестанет получать сообщения.
- Запуск — **на том же сервере**, что и старое приложение, отдельным docker-сервисом
  на своём поддомене. Доступ к серверу у пользователя есть («всё живое»).
- Нейросеть — **DeepSeek** (уже оплачен), ОДИН запрос на сообщение вместо 5–7.
- В базу идут все типы: вторичка, новостройки, дома/участки, коммерция; продажа и аренда.
- Аудитория: коллеги-риелторы (видят телефоны агентов по коду доступа) и
  покупатели (видят только контакт СТРЕЛ). Telegram не обязателен — обычный сайт.
- Стек выбран минимальный: Python 3.11+, Starlette + uvicorn, SQLite (+FTS5),
  стандартный urllib для HTTP. Без Postgres/Redis/RabbitMQ.

## Проблемы старой системы, которые решаем (подтверждены скриншотами)
1. **Дубли.** Старый бэкенд сравнивал «похожие» объекты только внутри одного
   подключённого номера (bot_id), объявления без адреса не проверял вообще,
   отпечаток = телефон+адрес (другой агент → новый объект).
   → `app/dedupe.py`: сравнение по всей базе по характеристикам; репосты одного
   текста распознаются по хешу и НЕ гоняются через нейросеть повторно.
2. **Заголовок ≠ описание.** «Площадь: 20 сот» → «Участок, 20 м²»; участку в хуторе
   приписан «ЖК МОЗАИКА» и район «Теплоэлектроцентраль» (LLM угадывал «по знанию
   Краснодара»). → `rules.py` различает сотки/м²; `geo.py` ставит ЖК/район только
   если они есть в тексте или однозначно следуют из ЖК/улицы по справочнику.
3. **Описание резалось** по пустым строкам до одного абзаца.
   → `rules.split_objects` режет только если в сообщении несколько цен.
4. **Поиск «движение» → 1058 объектов** (нечёткое сходство по длинным текстам).
   → FTS5 по словам с простым стеммингом (`search.py`).
5. **Карта**: подложка Carto без ключа («API KEY REQUIRED»), карта игнорировала фильтры.
   → OSM-тайлы, точки карты по тем же фильтрам; координаты — Nominatim с кэшем.

## Структура
- `app/config.py` — настройки из `.env`
- `app/textnorm.py` — нормализация текста (ё→е, регистр)
- `app/geo.py` + `app/data/geo_kb_raw.json` — районы (канон + жаргон: ФМР, Восточка, РИП…),
  377 ЖК, 1155 улиц (из geo_kb.sqlite старого проекта)
- `app/rules.py` — разбор правилами: цена, площадь/сотки, комнаты, этаж, телефоны, улица, тип, сделка, «куплю/ищу»
- `app/llm.py` — один запрос к DeepSeek, строгая JSON-схема
- `app/parser.py` — объединение ответа нейросети и правил, выбрасывает всё, чего нет в тексте
- `app/dedupe.py` — склейка дублей
- `app/ingest.py` — сохранить сообщение → разобрать → создать/обновить объект; заголовок, индекс
- `app/search.py` — фильтры, сортировки, фасеты, точки карты, карточка с историей
- `app/wappi.py` — опрос Wappi `/{api|tapi|maxapi}/sync/messages/all/get`
- `app/geocode.py` — Nominatim
- `app/worker.py` — фоновый цикл (`python -m app.worker`)
- `app/server.py` — веб/API (`uvicorn app.server:app --port 8090`)
- `web/index.html`, `web/app.js`, `web/style.css` — страница поиска. Фильтры хранятся
  в адресе страницы (ссылкой на поиск можно поделиться). Цена в фильтре: продажа — млн,
  аренда — тыс. ₽/мес. Карта — Leaflet + OSM + markercluster, ценники на точках.
- `tests/` — pytest (`pip install -r requirements-dev.txt && pytest`), 21 тест
- `Dockerfile`, `docker-compose.yml` (web + worker, общий том `./data`), `README.md` — деплой

Секреты не коммитить: `.env` в .gitignore.
